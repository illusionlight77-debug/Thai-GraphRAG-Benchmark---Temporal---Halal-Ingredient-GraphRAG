คำถามวิจัย

การดึงข้อมูลแบบมีโครงสร้างกราฟ (GraphRAG) ชนะการดึงแบบเวกเตอร์ (vanilla RAG) สำหรับคำถามภาษาไทยหรือไม่ และ ชนะตรงไหน

สมมติฐาน: ช่องว่างของ GraphRAG เหนือ vanilla จะกว้างขึ้นตามจำนวน hop (single → multi / relational) เพราะ vanilla ดึงโหนดที่คล้ายคำถามได้ แต่เดินตามความสัมพันธ์ไม่ได้

ตัวแปรที่เปลี่ยนมีอย่างเดียวคือ retriever — pipeline, embedding (bge-m3), LLM และ prompt ใช้ตัวเดียวกันทั้งหมด

1 · ภาพรวม — เปลี่ยนแค่ "ตัวดึงข้อมูล" เท่านั้น

คำถามเดียวกันวิ่งผ่าน pipeline เดียวกัน ใช้ embedding · LLM · prompt เดียวกัน ต่างกันแค่ retriever — ผลต่างของคะแนนจึงมาจากวิธีดึงข้อมูลล้วนๆ

2 · A (แกน) — Vanilla RAG ต่างจาก GraphRAG อย่างไร

ตัวอย่างคำถาม multi-hop: "ในจังหวัดเดียวกับมัสยิดกรือเซะ มีที่พักกี่แห่ง"

Vanilla เก่งเมื่อคำตอบอยู่ในโหนดเดียวที่ข้อความคล้ายคำถาม แต่คำถามที่ต้องเชื่อมสองโหนดผ่านโหนดที่สาม ไม่มีโหนดใดบรรจุคำตอบไว้ตรงๆ — GraphRAG เดินตามเส้นความสัมพันธ์จริงจึงประกอบคำตอบได้

3 · ข้างใน GraphRAG — 4 ขั้นตอน

1

Entity Linking — คำถาม → seed nodes

3 ชั้น: gazetteer (ชื่อจังหวัด/ภาค/หมวดที่ตรงเป๊ะ) → fulltext (Neo4j index ตัวตัดคำ thai) → n-gram + CONTAINS (fallback) ให้คะแนนด้วย Dice · ไม่แตะ Qdrant เพื่อไม่ให้กลายเป็น "vanilla + graph"

2

Seed card — บรรยายโหนดตั้งต้น

ดึงข้อความของ seed nodes มาตรงๆ — พอสำหรับคำถาม single-hop

3

Aggregated neighbourhood — สรุปเพื่อนบ้าน (ไม่ไล่ทุก path)

นับ + ตัวอย่าง ต่อ (ชนิดความสัมพันธ์ × ชนิดโหนดปลาย) ที่ฐานข้อมูล เช่น "(ปัตตานี) ← ที่พัก จำนวน 16: ..." · โหนด hub อย่างกรุงเทพฯ (เพื่อนบ้าน 3,746) จึงไม่ระเบิดเป็นล้าน path แล้วค้าง

4

Bridge paths — เส้นทางเชื่อมระหว่าง seed

shortestPath ระหว่างคู่ seed → หลักฐาน multi-hop โดยตรง · ทั้งหมด linearise เป็นข้อเท็จจริงไทย จำกัดที่ MAX_TRIPLES=60

4 · B (Temporal) — ตอบตามเวลา

สืบทอด GraphRAG ของ A แล้วกรองทุกความสัมพันธ์ด้วยช่วงเวลา

เปิด B ไม่ทำให้เสียข้อเท็จจริงไร้เวลา แค่ตัดข้อความที่ไม่จริงในปีนั้นออก

5 · C (Halal-Ingredient) — อธิบายเส้นทาง

คำวินิจฉัยเป็นสมบัติของ คู่ (ส่วนผสม, แหล่งที่มา) ไม่ใช่ของส่วนผสมเดี่ยว

ถามลอยๆ "เจลาตินฮาลาลไหม" คำตอบที่ถูกคือ "ขึ้นกับแหล่งที่มา" — ระบบ flat จะเลือกคำตอบเดียวมาตอบเป็นข้อเท็จจริง ซึ่งผิด

6 · A / B / C ประกอบกันอย่างไร

B และ C เสียบผ่าน get_retriever() และเพิ่มตัวเองเข้า benchmark — ไม่มีไฟล์ใน core ถูกแก้ · ลบ extension ทิ้ง แกน A ยังรันได้ปกติ
